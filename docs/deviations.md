# Deviations from the paper

Every difference between this replication and the original ConstraintBench paper ([arXiv:2602.22465](https://arxiv.org/abs/2602.22465)), with the reason. Add a row whenever a choice differs from the paper.

| # | Paper | This replication | Reason | Status |
|---|---|---|---|---|
| 1 | 10 domains, 20 tasks each | 4 domains first: facility location, shift scheduling, bin packing, crew assignment | Time budget. These 4 cover all four failure types the paper reports. | Planned |
| 2 | Problems generated by a LangGraph LLM agent (up to 9 attempts, with Gurobi IIS feedback) | Problems generated by seeded Python code; an LLM only writes the scenario text | Cheaper, reproducible, and lets us control problem size (needed for extension B). The paper doesn't publish the agent's prompts or model anyway. | Planned |
| 3 | GPT-5.2-pro, GPT-5.2, Claude Opus 4.6, Claude Opus 4.5, o4-mini, Gemini 3 Pro Preview | Models available at run time (listed here when chosen) | Some original models may be retired; budget. | Planned |
| 4 | Gurobi (version and license not stated) | `gurobipy` from PyPI with its size-limited license | Free. Problems small enough for a prompt should fit the limit. | Planned |
| 5 | Prompts and JSON schemas not published | Our own, versioned in `prompts/` | Not available. | Planned |

## Details the paper doesn't give

We choose these ourselves and document each choice here once it's made:

- The LLM used to generate scenarios, and the generator agent's prompts
- The industry context lists used for seeds (about 45 per domain)
- The answer JSON schema for each domain
- The MIP formulations for every domain except facility location
- The Gurobi time limit and version
- How the 20 tasks per domain were sampled from the verified pool
