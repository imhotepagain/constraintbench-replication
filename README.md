# ConstraintBench Replication

An independent replication and extension of **ConstraintBench** ([Tso et al., 2026](https://arxiv.org/abs/2602.22465)). ConstraintBench tests whether large language models can solve constrained optimization problems *directly*: read a business problem and answer with a solution, without writing solver code.

> This project is not affiliated with Haladir Research or the paper's authors. The original benchmark and code were not public when this project started (October 2026), so the problems, prompts and checkers here are rebuilt from the paper's description. Every difference is listed in [docs/deviations.md](docs/deviations.md).

## The question

LLM agents are increasingly asked to make operational decisions such as shift schedules, delivery routes, or where to open a warehouse. ConstraintBench asks whether a model can produce a plan that **breaks no rule** (feasible) and is **as good as possible** (optimal). Answers are checked against the exact optimum found by the Gurobi solver.

The paper tested 6 frontier models on 200 problems in 10 domains. Its answer is that models can't do this reliably:
- The best model's plans were feasible only 65% of the time.
- No model was both feasible and optimal on more than 30.5% of problems.
- When plans were feasible, they were usually close to optimal, so the main weakness is satisfying every constraint.

## What this project does

1. **Replicate** the benchmark on 4 domains (facility location, shift scheduling, bin packing, crew assignment) and check whether the paper's findings hold.
2. **Improve the method:** several attempts per problem with confidence intervals, and problems generated by seeded code for reproducibility.
3. **Extend** it:
   - **Feedback loop:** does telling the model which constraints it broke make it reliable, and at what cost?
   - **Difficulty scaling:** at what problem size does each model break down?
   - **Direct answer vs. solver code:** how much does letting the model write Gurobi code help?
   - **Training a small model** with the checker's score as a reinforcement-learning reward (later, once compute is funded).

Roadmap and progress: [PLAN.md](PLAN.md).

## Status

Early stage: milestone 1, understanding the paper. No results yet.

## Setup

Requires [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/imhotepagain/constraintbench-replication.git
cd constraintbench-replication
uv sync
cp .env.example .env        # add API keys for the providers you plan to use
uv run python scripts/check_env.py
uv run pytest
```

Gurobi installs from PyPI with a free size-limited license, which is enough for problems small enough to fit in a prompt.
